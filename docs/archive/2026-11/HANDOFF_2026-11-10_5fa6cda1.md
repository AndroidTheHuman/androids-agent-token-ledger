## Judgment calls

1. **One formatter for METRICS.md and the browser** (the owner chose "one formatter for both"; how was mine). A page opened from disk cannot import TypeScript. Options: (a) a copy in `index.html` plus a test that the two agree; (b) percentages pre-formatted by the tool into `data.js`; (c) the formatter's source as one string that the tool builds `pctOf` from and `data.js` ends with. I took (c): one source, and the browser runs exactly what `METRICS.md` used. The cost is a `new Function` over a constant string in `src/format.ts`. (b) was out: the privacy test's token pattern rejects `%` and `$`, and `data.js` would have needed a wider allow list.
2. **The previous handoff's proposed line "report.ts rounds shares twice" was not merged.** It describes a bug this session fixed, so it would have been false once committed. Everything else it proposed was merged (`2a17616`).
3. **Panel 3 draws the game's committed ledger (`game-ledger.json`, 207 sessions), not `sessions.json`.** E1's windows have no surviving transcripts, so `sessions.json` would show nothing around the rule the register tests most. The 37 ledger rows without a transcript are hollow dots, which `sessions.json` decides. The other projects' 4 sessions are counted in the caption and not plotted: one of them is from March and would have stretched the axis.
4. **Markers: E1 to E4 and X1, as the brief says.** X2 is in `rules.json` (date only) and not drawn (IDEAS).
5. **`data.js` freshness.** The brief's checkpoint asks that `summary` deep-equal `summary.json`. I test that, and equality of `sessions`, `game` and `rules`, and that the file is what the tool writes. For `own` (this project's ledger) I only require its ids to be a prefix of the ledger's: `npm run sessions` runs after the dashboard was last built, and an exact test would turn the gate red at every handoff. The cost: panel 5 can lag the ledger by one session until `dashboard` is run again (the README and the panel's caption say so).
6. **Colours.** Token types take categorical slots 1 to 4 and projects take 5 to 8, so no colour means two things on the page; the game's colour is the same in panels 2 and 3. I ran the validator only on slots 5 to 8 (the ones I chose); 1 to 4 are the skill's documented adjacent run.

No theme toggle: the page follows the system setting.
8. **"How this was built" cites the ledger, not `summary.json`.** So the figure check on FINDINGS (part C's checkpoint) stops before it; I changed the git-ignored script and not the checkpoint's meaning.
9. **Expected numbers that missed.** The previous handoff expected `triage-r1.mjs` to print nothing after the fix; it checks the stored share, so it cannot (see the rounding fix's Risk). I replaced the check with the test. Every other checkpoint number matched.
